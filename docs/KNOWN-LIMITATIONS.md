# 已知限制

- Windows x64；一场活动、最多 30 人，一个组织者宿主。
- 业务事件暂未使用端到端加密，活动房间成员可读快照和消息。
- 关闭应用后停止自动同步；后台唤醒、手机适配和多活动在后续版本。
- 模型通过官方宿主服务使用，后台 octos Agent 内核尚未配置；本版
  不包含关闭应用后自主执行的能力。
- 自动检查每次完成后等待下一次间隔。服务端响应较慢时，实际更新会
  延后；本机真实测试观测约 5–51 秒，界面会显示最近一次检查时间。
- 服务器历史缺失、分页不完整或状态冲突时停止推进。服务器时钟无法
  核实时本轮不释放过期名额；本机时钟与服务端相差超过 30 秒需校准。
- 无法证明发送结果的操作保持“待核实”，不盲目重发。核实可能需要
  网络恢复和完整历史；无法证明未发送时不能自动释放不确定邀请。
- 房间创建和成员加入需独立核对。发生超时先在 Rinx 查看已有房间和
  成员状态，避免自动重复创建。
- 固定 Makepad 会记录一条隔离 VM 更新被安全延迟的诊断。启动检查
  只允许这一条已核对的诊断，其他错误仍阻止验收。
- MiniMax 使用量费用是估算；开发预留与实际扣费分别显示。尚需在
  供应商账单核对实际金额，轮询同步不调用模型。
- 公开稳定版本取决于发布验收，不以源码版本号或历史预览检查代替。
