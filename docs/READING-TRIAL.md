# 三个身份验证读书会补位

使用两台 Windows，组织者和两名成员分别登录自己的 Rinx 身份。手机可辅助检查消息送达；补位的报名与更正使用 Windows 入口。组织者只运行一个宿主。

## 准备

1. 两台电脑完整解压同一版本的 Windows 运行包，安装使用指南中的微软运行库。
2. 本机打开“启动组织者.cmd”和“启动参与者.cmd”，分别作为组织者、成员 A。第二台电脑打开“启动参与者.cmd”，作为成员 C。
3. 各自登录，在“账号与设置”核对账号并确认业务权限。不要复制另一人的登录资料或密钥。需要 AI 更正的成员 C 在本机配置本人可用的 Kimi Code K3；也可手动编辑并确认本次安排。
4. 在 Rinx 建立组织者与两名成员的聊天关系。组织者创建未来日期的读书会，时间 19:30–21:30，容量 **1 个参与席位**，组织者另计。预览后把活动卡片分享给 A、C。

## 完整故事

1. A 从卡片进入，按全场时段报名；组织者确认本场自动补位规则。A 收到邀请，亲自接受，双方等待“报名已确认”。
2. C 保存本场参与目标，同行人数 1，可用到 20:30；另行确认报名，保持候补。
3. A 本人预览并确认取消。组织者首页应出现人数缺口，说明 C 的登记时段不覆盖 21:30 的活动结束时间。
4. C 打开原目标的“更正这次安排”，输入“这次能待到晚上九点半，还是我一个人”。核对原值、新值和原话，点击“确认更正：仅本次”。
5. C 点击“另行预览本场候补更新”，核对本场活动、19:30–21:30 和 1 人，再确认报名更新。这一步与目标更正分别确认。
6. 双方等待宿主核验。原排位保持，自动补位邀请 C；C 本人接受，组织者最终看到 **1/1 报名已确认**。

## 记录结果

记录使用版本、三个独立身份、开始与完成时间、人工操作次数和检查次数。核对 C 的长期偏好未改变、原候补顺序和任务保留、每次发送只有一个服务端事件。

实际到场及读书会体验另行反馈。试用录屏前取得参与者同意，公开视频遮盖账号、房间编号及私有内容。网络中断时先查看“活动记录”，沿原编号核实结果，再继续原任务。
