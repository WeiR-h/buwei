# 可复用的授权与回执框架

`native/crates/action-receipts` 是 Apache-2.0 Rust 通用库，提供
`prepare → confirm → execute → reconcile → receipt`。补位、参与者回复
和文章以各自适配器实现业务校验与服务端证据核验。

## 可评审范围

- 宿主授权绑定账号、权限、有效期与授权代次。切换账号、撤销授权和
  修改内容后，旧确认失效。
- 发送前写入 SQLite 执行记录，通过条件更新限制并发执行。
- 不确定结果保留原编号，重启后用新授权查询服务端证据，不能直接
  再次发送；回执必须匹配账号、对象、摘要及原操作编号。
- 回复自身编号与关联邀请编号分别保存，避免把同一邀请误计为多次
  执行或错误去重。
- SDK 收件去重与业务变更同一事务提交，完整历史与同步进度分别保存。

## 证据边界

规则及并发测试使用模拟适配器；真实双账号验收通过官方 SDK。
故障构建显式启用 `acceptance`，模拟发送前传输不可用、服务端接收后
丢失回执，以及原生进程在保存回执前中止。运行包不编译验收控制。

受控基线使用同一 SDK 和丢失回执故障，移除框架执行与恢复逻辑后，
以新编号重试。其服务端事件数与接入框架后的原编号恢复结果比较。
这是可复现的受控比较，不能代替历史产品的实测记录或官方合并结果。

贡献补丁与验收统计随发布附件提供。补丁尚未提交或被官方合并，
源码公开与比赛主办方确认分开记录。
