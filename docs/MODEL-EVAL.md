# 模型辅助与真实测试

## v0.1.1 小版本

开始使用页支持需求追问：

1. 填写原需求，点击“生成本人偏好建议”。
2. 未给出的时间和人数显示“待补充”，并列出具体问题。
3. 在补充回答框填写答案，点击“提交补充，继续理解需求”。最多补充三轮。
4. 信息完整后核对时段和人数，点击“核对建议并预览报名”。
5. 在动作确认页另行确认发送。模型调用本身不会报名或占位。

修改原需求后重新生成。修改最后一条补充回答、切换账号、活动版本变化、
撤销或过期授权，都使原建议无法进入旧的报名确认。
当前版本支持今天的整数小时；分钟、其他日期和跨天需求保留为待澄清。
这些情况需要修改原需求，写清受支持的时段，或使用手动填写。

组织者的匹配解释先读取业务规则计算的下一位候补，再核对模型返回的序号。
重新报名者排在新的队尾。名额预留与本人接受分别说明。
活动小记仍是待审草稿，需要另行保存、预览和确认发布。

## 合成案例运行器

`tools/model_suite.py` 生成 62 项虚构测试，不包含真实姓名、账号、房间编号、
活动标题、登录会话或密钥。测试通过官方 `ModelHost` 调用 MiniMax-M3，
复用应用相同的请求、结构校验、时段限制、匹配检查和草稿检查。
它不打开 Matrix 会话、不写业务数据库，也不发布任何消息或文章。

测试涵盖整数时间、中文数字、缺失字段、模糊上午下午、同行总人数、
分钟和跨天、超范围值、冲突需求及诱导执行指令；还包括多轮补充、
重新报名、暂停、满员、已有预留和 30 人边界。

先在应用中配置本机加密密钥，然后关闭使用同一资料目录的宿主。
使用已经配置好的资料目录运行：

```powershell
python tools/model_suite.py .run/model-suite.json
$buweiEvalProfile = Join-Path $env:LOCALAPPDATA 'BuWei/v0.1.1-organizer'
& ./native/target/debug/buwei-rinx-dual-host.exe $buweiEvalProfile --model-eval .run/model-suite.json .run/model-results.json
```

可以用 `--first 2` 先生成两个配置检查案例。每项结果都会保存实际请求、
输出、期望结果、请求摘要、采集时间和提供方报告的 Token 用量。
中断后使用同一测试集和结果文件恢复，已保存的项不会重新调用。
提示说明或版本变化后应使用新结果文件，原记录保留。

## 用量和费用

普通应用继续保持每分钟 3 次、每天 20 次、每天 30,000 Token 的限额。
显式运行的合成测试使用 `buwei-evaluation-v1` 计数，最多每分钟 3 次、
每天 80 次、每天 180,000 Token。UTC 日更换时计数重置，原限额保留。

两种入口共用资料目录已有的模型预算记录，每次提供方尝试先预留 0.10 元，
最多预留 10 元；失败及结构修复重试也计入。重启不会补回预留，升级继续
复制现有计数。测试不自动购买额度或修改正式应用的限额。

预算先落盘，再调用提供方。v0.1.1 增加提供方返回的输入、输出 Token 累计，
旧调用的估算金额保留；结构校验失败的已收到响应也记录用量。
估算采用输入 2.10 元、输出 8.40 元每百万 Token 的标准价格，缓存折扣未计入。
测试不请求优先服务。价格来源：[MiniMax 按量价格](https://platform.minimax.cn/docs/guides/pricing-paygo)。

预留金额、费用估算和实际账单是三个不同的数。账户余额和领券到账情况
需要在 MiniMax 控制台核对，测试结果不能证明实际扣费或剩余额度。

## 结果范围

自动检查可以证明结构、确切偏好、追问阻断、候补序号一致和没有业务执行。
文章措辞和解释仍需人工审阅，有限案例通过也不代表所有自然语言均可正确理解。
真实模型报告与界面检查另行记录，v0.1.0 的冻结发布材料保持固定。
