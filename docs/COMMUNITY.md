# 从活动策划到社群报名

组织者在“新建活动”描述想办的活动，或在已配置模型的 OctoSense 系统智能体中请补位准备策划。草稿保存目标、活动基础信息、流程、准备事项、招募文案和提醒建议。没有模型时，可以直接使用模板填写。

1. 核对时间、地点和人数，点击“核对并预览创建”，然后确认创建。流程与提醒是可编辑建议，保存策划不会预约场地或启用提醒。
2. 在“社群活动”选择本人已加入的 Rinx 普通活动社群，预览并确认发布当前活动卡片。若希望自动处理社群成员的加入申请，另行查看规则并确认启用。
3. 成员在同一页面挑选活动，核对本人加入申请并确认。收到房间邀请后点“加入并准备报名”，核对整场时段和同行人数后确认报名。已接入的活动可点“参加整场 · 准备报名”；有时间限制时仍可自行填写，或用自然语言补充和更正。

房间访问与名额分开处理。获得房间邀请不表示报名成功；候补收到名额邀请后仍由本人接受。组织者可以在活动详情查看完整名单，并选择本机保存位置导出 CSV。成员页面展示本人报名信息和人数汇总。

每个人都能新建活动。“我组织”和“我参加”按每场活动判断；从参与者入口启动也可以组织自己的活动。日常使用“启动补位”，另两个入口用于分别保存两个账号的资料。每个账号当前最多接入五场有效活动，各场人数和回执分别核验。

“参加整场，两个人”“我想参加整场,2人”等明确表达会直接使用当前活动的完整时段，并保留本次人数；结果仍需本人确认。这些表达不调用模型、不修改长期偏好。附加离开时间、人数未定或其他限制时，继续使用原追问和更正流程，不会擅自套用整场时段。

## 公开活动与社群活动

“公开活动大厅”使用当前 Matrix 服务器的 `#buwei-events` 别名。首次进入会显示公开范围：如果大厅尚不存在，确认后创建；已有大厅则确认加入并核验来源。后续打开已核验的大厅直接读取活动。所有 Rinx/Matrix 用户均可加入大厅查看公开介绍，安装补位后可以选择活动、提交本人加入申请。

组织者在大厅选择自己的活动，预览并确认“发布为公开活动”。选择“我的社群”及本人已加入的普通私密社群时，卡片只发到该社群。公开房间不能误标成仅社群可见。发布介绍不改变活动房间的邀请规则；组织者另行确认加入规则后，才按来源和成员身份处理申请。

公开介绍包含活动名称、时间、地点、组织者、活动定位和发布时空位；大厅成员身份及加入申请可被其他大厅成员看到。报名名单保存于对应活动房间，私人目标和长期偏好留在本人本机。公网目录服务故障、组织者离线或授权到期时，申请保留为待处理，不表示报名成功。

## 策划修改与恢复

在原策划稿填写补充内容，点击“AI 合并本次补充”。未提字段保留，修改字段取消旧确认。核对后重新保存基础信息，再预览创建。已进入创建的策划不能用新稿覆盖；网络结果不明时使用“恢复待核实的活动创建”，沿原编号查找房间。

策划稿按本人账号保存在本机。切换账号不能读取其他账号的策划。系统智能体的两个工具只保存或读取策划稿，工具参数不能声明身份，也不能创建、分享或替人报名。

在补位核对本人账号并授权后，按 F8 打开 OctoSense 系统智能体，可以请它“用补位准备读书会策划稿”，或读取原稿后补充安排。系统智能体沿用宿主自己的模型设置；应用内的一句话入口使用补位的本机模型配置。两者写入同一份策划稿，实际创建仍在补位中核对并确认。

## 社群访问与异常处理

仅读取本人明确选择的社群。活动卡片显示发布时的信息，进入活动房间后再核验最新资料。本轮支持可由当前宿主核验的普通活动社群；加密群会提示另选房间，避免把明文活动资料发进加密群。

加入申请的发送者、活动定位和事件编号记录在所选社群中，不包含本人可用时段和私人偏好。组织者核验申请者当前的社群成员身份，再按已确认的规则发出活动房间邀请。规则最多处理 30 次新邀请，到期不超过一小时授权和活动开始；撤销、暂停或退出后停止新邀请。

组织者离线或规则未启用时，成员申请保留为待处理。发送结果不明时使用“核实社群操作回执”，先查询原编号，不另发相同申请。重启后重新授权；已有请求与回执保留，自动邀请规则需重新确认。

## 名单导出

导出包含报名序号、显示名、Matrix 身份、同行人数、可用时间和状态，并注明活动编号、导出及核验时间。同行成员按人数统计，不推测未登记成员的姓名。CSV 使用 UTF-8 BOM，可由 Excel 打开；文本字段按普通文字保存，防止被解释成公式。

导出只保存到组织者确认的本机路径，不自动上传。名单、账号或保存文件在预览后发生变化时，需要重新预览导出。
