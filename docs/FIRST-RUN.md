# 开始使用补位

## 准备

Windows 10/11 x64，系统图形与媒体组件，以及 [微软 Visual C++ v14 x64 运行库](https://aka.ms/vc14/vc_redist.x64.exe)。完整解压运行包，保留字体、资源和工具目录。双击“启动组织者.cmd”或“启动参与者.cmd”；两个入口的资料目录独立。

在 Rinx 登录 `matrix.rinx.chat`，浏览器验证由本人完成。看到 “Let Rinx's agent start?” 时选择 **Don't allow**，然后继续登录。在补位“账号与设置”核对本人账号，查看权限并确认授权。登录和业务授权分别确认。

## 组织一场活动

1. 新建活动，选羽毛球、桌游或读书会模板，填写完整日期、时间、地点和容量。时间按北京时间保存，跨午夜时填写不同日期。
2. 选择已在 Rinx 建立聊天的联系人，预览活动卡片，确认分享及成员邀请。
3. 查看报名与候补。手动邀请逐项预览确认；启用“自动补位”时先核对本场规则、发送时段和授权额度。
4. 名额保留、邀请送达和本人接受分别显示。只运行一个组织者宿主；应用打开且授权有效时同步回复并递补。
5. 活动结束后归档，在活动小记中生成或编辑草稿，预览全文再确认发布。复制下一场会保留设置，日期重新填写，成员重新报名。

同时最多五场活动；每场最多 30 个名额和 30 条有效报名。每条报名 1–8 人，整组邀请和接受；名额不足时跳过该组，保留排位。

首页集中展示活动卡片。点击卡片或“查看当前活动”打开详情，查看名额、候补和本场规则；“返回活动列表”可切换其他活动。手动邀请入口也在详情中。

## 参加活动

从 Rinx 活动卡片点“查看并报名”，核对本人账号并确认加入活动房间。填写可用起止日期时间和同行人数，预览后确认报名。收到邀请后本人预览接受或拒绝，再确认提交。回复送达后等待组织者核验，最终结果显示“报名已确认”。取消也需本人确认。

AI 可理解自然语言并追问缺失内容；也可直接手动填写。当前名额已为本人保留时，先接受或拒绝这份邀请，再处理取消。

## 自动补位

默认按报名先后选择时段匹配、人数可容纳的候补；邀请有效十分钟，最迟到活动开始；发送时段为北京时间 08:00–22:00。可在确认规则前设为 5–60 分钟和指定发送时段，每次授权最多 30 次新邀请。

授权最长一小时，到期前五分钟提示续期。撤销、到期、规则修改、账号变化或真正退出后暂停发送；重启需重新确认。每轮先核实回复，再释放过期名额。主动开启托盘值守时，关闭主窗口后仍按有效授权运行，可从托盘暂停或退出。

## 让补位持续关注目标

在“我的目标”保存办活动的目标或参加意愿，首页会依据核验结果准备相关建议。进入“活动记录”继续任务或查看回执。长期偏好单独确认；反馈可选择“仅本次”或“更新长期偏好”并撤回。

在“账号与设置”开启Windows托盘值守和可选的主动AI分析。两项分别开启；账号授权到期后停止受授权约束的读取、模型调用和发送。详见[目标、主动建议与值守](INTENTIONS.md)。

## 模型设置

在“账号与设置”选择配置 MiniMax 密钥，在独立本机窗口填写。密钥由当前 Windows 用户加密保存；固定使用 MiniMax-M3。没有配置时继续手动创建和报名。活动问答和小记引用本场记录。

## 中断与升级

在“活动记录”沿原编号核实待恢复回执。重启后重新授权，先核实旧操作。网络异常时保留原编号和名额，避免重复发送。创建结果不明时使用原创建恢复入口。

升级前关闭旧版，使用 `tools/migrate.py 旧资料目录 新资料目录 --from-version 旧版本 --to-version 新版本` 复制并核验。旧程序和目录保留，有效授权不迁移。迁移失败时回到旧入口并保留记录。
